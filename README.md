# 🕊️ 推特用户画像生成器

一个**通用化**的推特数据系统：输入目标对象、若干个 cookie、LLM API Key，
一键完成 **抓取推文 → 清洗统计 → LLM 总结 → 生成完整用户画像**，
全流程在浏览器图形界面中完成。

## 功能

- **两种提取模式**
  - 用户模式：归档某用户全部推文（近端主推文 + 近端含回复 + search 按月补历史）
  - 关键词模式：按关键词 / 标签按月搜索抓取
- **自动起始日期**：起始日期留空自动选取——用户模式 = 账号创建月起（不早于 2010-01），关键词模式 = 2010-01-01；也可手动指定精确范围
- **多账号轮换**：cookies 每行一个小号，自动轮换突破单账号限流
- **每账号独立代理**：行尾 `|proxy=` 指定独立出口 IP，绕开按 IP 限流
- **断点续跑**：按月落盘，中断后重启自动跳过已完成部分
- **数据清洗**：去重、排序、日期过滤、文本清洗
- **统计分析**：总量、按年分布、互动数据、热门标签、高频提及；ACG 预设额外统计职业线索（画师/剧本/声优/动画/音乐/宣发/活动/联动）与媒体特征
- **LLM 画像（多预设）**：分层采样 + 分批分析 + 综合生成 Markdown 画像（支持任意 OpenAI 兼容接口）
  - 采样面向画像优化：高互动 Top（原创加权）+ 创作/媒体类优先 + 按年分层
  - 预设可选：ACG 从业者（默认）/ 通用个人 / 品牌官方号 / 内容创作者 / 专家意见领袖，各预设按对应群体的维度组织画像章节
  - 每个预设均含「人物历程（时间线）」与「数据来源与可信度」章节：关键结论注明推文链接与日期
- **四种操作（功能拆分）**：抓取 / 导入 / 导出 / LLM 总结互相独立，**不填 API Key 也能用**
  - 完整流程 / 仅抓取 / 导入数据（已有 CSV）/ 仅 LLM 总结（已有数据）
  - 抓取、导入、导出、清洗统计完全不依赖 LLM；仅生成画像时需要 API Key
- **简约推文整理**：每条推文仅含时间、链接、内容的 `tweets_digest.txt`，可一键下载导出
- **防休眠与自动关机相互独立**：防休眠（任务期间系统不休眠、允许息屏）默认开启；自动关机（成功后 60 秒内关机、可取消）单独勾选
- **限流状态检测**：一键轻量探测当前是否处于推特限速（429）或 Cookie 失效（401/403）
- **多配置文件**：可保存/切换/重置多套命名配置（`configs/<名称>.json`），切换自动载入表单
- **统一用户数据目录**：Cookie / API Key / 账号库等隐私数据与抓取数据统一存放在 `~/TwitterProfileGenerator/`（可用环境变量 `TPG_DATA_DIR` 覆盖），与程序目录分离；首次启动自动迁移旧版散落在程序目录的数据
- **自定义输出目录**：界面可一键选择抓取数据与结果的保存位置（系统目录选择框或手动粘贴路径），自动保存并在下次启动时恢复；任务运行中禁止切换
- **日期快捷选择**：近1年 / 近3年 / 近5年 / 全部 / 自定义 一键设定
- **线性流程进度可视化**：抓取 → 清洗统计 → LLM 总结 三步步骤条（进行中/完成/失败/跳过）+ 整体进度百分比图表，明细可折叠
- **输出内容自动保存**：任务成功完成后，输出自动归档到 `output/<任务>/history/<时间戳>/`（保留最近 20 份），历史可追溯，不会被下次运行覆盖
- **工作原理文档**：界面「工作原理」按钮在线阅读完整原理说明（`/docs`）
- **详细状态界面**：任务信息 / 运行时长 / 逐阶段明细（抓取条数、清洗去重、LLM 批次）/ 带时间戳的事件日志
- **图形界面**：手工绘制内联 SVG 图标与空状态插画、模式/预设联动提示、回车快捷启动、运行中自动隐藏旧结果、下载按钮（零前端依赖）

## 安装

```bash
pip install -r requirements.txt
```

## 运行

```bash

python app.py 8080       # 指定端口
```

浏览器打开 http://127.0.0.1:8001

## 使用步骤

1. **填写配置**
   - 模式：用户 / 关键词；目标对象
   - 操作：完整流程（默认）/ 仅抓取 / 导入数据 / 仅 LLM 总结
   - 画像预设：ACG 从业者（默认）/ 通用个人 / 品牌官方号 / 内容创作者 / 专家意见领袖
   - 起止日期：起始日期留空自动选取（用户模式=账号创建月起），也可手动指定或使用快捷按钮（近1年/近3年/近5年/全部/自定义）
   - Cookies：每行一个小号，三种填法任选
     - ① 直接填两个值：`token值 ct0值`（自动补前缀，最简单）
     - ② 完整格式：`auth_token=xxx; ct0=yyy`
     - ③ 整段粘贴 Cookie 头：`Cookie: auth_token=xxx; ct0=yyy; twid=z`（自动提取）
     - 可选 `|proxy=代理地址`；`#` 开头为注释；输入时界面实时显示"已识别 N 个小号"；可点「检测限流状态」确认是否被限速
     - 已保存的 Cookie 不会明文回传到界面（掩码为"已保存"），可直接使用已保存配置启动任务，无需重复粘贴
     - 已保存的 LLM API Key 同样不回传明文，启动完整流程 / LLM 总结时自动复用已保存 Key
   - LLM：API Base URL（OpenAI 兼容）+ API Key + 模型名（仅生成画像时需要）
   - 电源：防休眠（独立勾选，默认开）；完成后自动关机（独立勾选）
   - 配置文件：默认 `user_config.json`，也可切换/新建命名配置
   - 输出目录：默认存到数据目录 `output/`，可点「选择…」改到任意位置（自动保存、下次启动自动恢复）；「打开输出目录 / 打开数据目录」一键在文件管理器中定位
2. 点击 **🚀 开始生成**（输入框内按回车也可快捷启动；导入操作改为选择 CSV 后点「导入并清洗」）
3. 等待实时进度完成（抓取 → 清洗 → 分析）
4. 查看统计卡片与最终画像，可下载清洗 CSV、简约整理（时间/链接/内容）与画像 MD
5. 界面右上角「工作原理」可在线阅读完整原理说明

## 获取 Cookie（auth_token / ct0）

> ⚠️ 务必使用**小号**，不要用主号（有风控风险）

1. 打开 https://x.com 并登录小号
2. F12 → Application → Cookies → 选择 `https://x.com`
3. 复制 `auth_token` 与 `ct0` 的 Value
4. 填进界面 Cookies 输入框（每行一个小号）

## 目录结构

```
twitter_profile_generator/          # 程序目录（只放代码与只读资源）
├── app.py              # Web 界面 + 流程编排
├── scraper.py          # 通用抓取引擎（含自动起始日期）
├── processor.py        # 清洗与统计（含 ACG 职业线索统计、画像采样、简约整理）
├── llm_analyzer.py     # LLM 画像生成（多预设 PRESETS、人物历程与来源标注）
├── paths.py            # 路径管理（程序目录 / 用户数据目录 / 输出目录）
├── static/index.html   # 前端界面（内联 SVG 图标）
├── static/工作原理.md  # 工作原理文档（界面「工作原理」按钮可读）
├── tests/test_core.py  # 核心逻辑测试（不联网）
└── requirements.txt

~/TwitterProfileGenerator/          # 统一用户数据目录（隐私数据 + 获得的数据）
├── user_config.json    # 主配置（Cookie / API Key 等，掩码回传）
├── configs/            # 命名配置文件（configs/<名称>.json，可选）
├── accounts.db         # twscrape 账号库
├── progress.json       # 任务进度
├── app_settings.json   # 界面偏好（如自定义输出目录）
├── 运行锁.lock         # 单实例锁
└── output/             # 抓取数据（可按界面「输出目录」改到任意位置）
    └── <模式_目标>/     # 按目标隔离：分片/CSV/画像/简约整理/history 归档
```

> 输出按目标自动隔离：每次抓取写入 `output/<模式_目标>/`（如 `output/user_elonmusk/`、
> `output/keyword_机器学习/`），**切换目标不会与上次数据串扰**；同目标重复运行仍走断点续跑。

> 隐私数据（Cookie / API Key / 账号库）与抓取数据统一存放在用户数据目录，
> **程序目录不再产生任何数据文件**；可用环境变量 `TPG_DATA_DIR` 指定其他位置。
> 旧版散落在程序目录的数据（`user_config.json` / `configs/` / `output/` 等）首次启动时自动迁移。

## 打包为独立软件（exe）

双击运行 `dist\推特用户画像生成器.exe` 即可（自动打开浏览器，无需装 Python）。

重新打包（修改代码后）：

```bash
build_exe.bat
```

产物在 `dist\`。打包要点：
- 入口是 `launcher.py`（启动服务 + 自动开浏览器 + 异常写「软件错误.log」，日志在用户数据目录）
- `paths.py` 区分打包内只读资源（static，exe 内）与用户数据目录（`~/TwitterProfileGenerator/`，隐私数据与抓取数据统一存放）
- PyInstaller 需 `--collect-all twscrape --collect-all fake_useragent`（已写入 build_exe.bat）

## 注意事项

- 安全：Cookies 与 API Key 经 `/api/config` 读取时均被掩码（不回传明文）；启动任务时由后端从本机配置直接读取，凭据不离开本机。- 国内访问 X 需要代理：脚本自动探测本机 Clash/v2rayN 端口，也可手动填全局代理
- 单账号限流很严（约 300 条/15 分钟），多账号 + 多 IP 是提速关键
- search 抓不到历史回复；近期回复由 `user_tweets_and_replies` 通道补充
- 程序内置单实例锁（`运行锁.lock`），重复启动会自动拒绝；异常退出留下的残留锁会在下次启动时自动接管
- 若旧实例卡死/无法退出，可用 `python launcher.py --force`（或 `app.py --force`）强制结束旧实例并接管运行锁；源码/批处理运行时也会在检测到旧实例后提示输入 `y` 确认强制接管
- 同一时刻请只运行一个抓取进程，避免多个进程抢同一批账号
